## 1. 测试目标与判定原则

测试不只验证页面“能用”，还要证明：

1. 需求覆盖：研发、生产、质控、管理和决策角色的关键任务存在完整闭环。
2. 权限正确：菜单、API、数据域三层均执行最小权限，不能只依赖前端隐藏按钮。
3. 数据可信：PostgreSQL、MongoDB/GridFS、Redis 之间发生超时、重试、并发或局部失败时，不丢数据、不重复、不产生不可发现的孤儿记录。
4. 可追溯：原始数据、每次变更、审核、发布、导出、共享、权限变更均能归属到用户和可信时间，且审计证据不可由普通管理员篡改。
5. 安全合规：满足已承诺的 ALCOA+、ISO 13485、FDA 21 CFR Part 11 和 GDPR 所需的产品控制与可验证证据；不能仅以文档声明代替实现和测试。
6. 可运行：关键性能、备份恢复、浏览器兼容、容器化部署和故障恢复达到约定指标。

验收门禁采用“关键用例 100% 通过”而不是笼统的“总用例通过率 98%”。涉及认证、授权、数据域、审计、电子签名、备份恢复和跨库一致性的 P0/P1 用例只要有一项失败，即阻止上线。

## 3. 首批验收纵切片

首批开发不应只完成零散 CRUD。建议按下列端到端纵切片交付，每条都同时覆盖 Vue 页面、Spring Boot API、PostgreSQL、MongoDB/GridFS、Redis、权限、审计和测试：

1. **身份与权限**：注册/管理员激活→登录→刷新→退出→冻结→改密；不同角色和部门对相同 API/记录得到正确结果。
2. **模板与受控版本**：创建私有模板→提交公共模板→审核电子签名→发布→基于已发布版本创建数据集→新版本不破坏旧数据。
3. **数据录入与附件**：动态表单校验数值、单位、时间和必填项→上传附件→暂存→提交→审核→发布；失败重试不产生重复或孤儿。
4. **领域追溯**：材料批次→工艺批次→零件/产品→质量检测/性能→附件，支持正向和反向查询，变更后仍可重放历史状态。
5. **导入导出**：Excel/JSON 批量导入，逐行错误报告与部分成功策略明确；按权限导出字段和附件压缩包，审计中包含范围、数量、校验和而不泄露敏感内容。
6. **外部接入模拟**：MES 增量同步和回调、PLM 物料/BOM、ERP 原材料检验、至少一种设备数据；覆盖乱序、重复、超时、断点续传和死信/补偿。
7. **备份恢复**：制造跨库一致业务快照→备份→破坏性测试环境恢复→对账→追溯与电子签名仍可验证。

## 4. 权限与状态验收矩阵

在代码出现后生成完整矩阵；最低必须覆盖以下维度的笛卡尔组合，而不是仅测四个“正常角色”：

- 主体：匿名、访客、普通用户、研发、生产、质控/审核员、管理员、被冻结用户、已离职用户、服务账号。
- 数据域：本人、同部门、子部门、同项目、跨部门共享、未共享域、已撤销共享。
- 操作：创建、查询、修改、删除/停用、审核、发布、导入、导出、下载附件、共享、分配权限。
- 状态：草稿、待审核、驳回、已通过、已发布、已停用、已归档、已逻辑删除、历史版本。
- 接入路径：页面、直接 API、批量接口、搜索、导出、GridFS 下载、后台任务、外部开放 API。

必须包含 IDOR/水平越权用例：用 A 用户合法获取的 ID、Mongo ObjectId、下载地址或任务 ID，由 B 用户直接请求；期望返回 403/404 且不泄露资源存在性或元数据。

## 5. 自动化测试分层

### 5.1 后端

- 单元测试：状态机、权限合并、数据域表达式、模板校验、单位/时间转换、幂等、脱敏、审计事件和异常映射。
- Web 切片测试：认证/授权过滤器、参数边界、统一错误体、分页排序白名单、上传下载响应头。
- 数据层测试：真实 PostgreSQL、MongoDB、Redis 容器，不用 H2 代替 PostgreSQL；验证迁移、索引、唯一约束、JSONB、GridFS、TTL/过期和事务回滚。
- 集成测试：推荐 Testcontainers 启动 PostgreSQL、MongoDB、Redis；测试跨存储 Saga/Outbox、Redis 重启/丢键、Mongo 主节点切换和 PostgreSQL 短暂断连。
- 契约测试：从 OpenAPI 校验请求/响应、错误码、鉴权要求；外部系统使用契约桩并保存版本化样本。
- 架构测试：模块依赖方向、控制器不直接访问仓储、跨域查询必须经过授权策略、日志禁止敏感字段。

### 5.2 前端

- Vitest + Vue Test Utils：动态表单、模板步骤状态、校验、权限指令、错误提示、分页筛选、上传断点和 Token 刷新并发。
- Playwright：上述七条纵切片；至少在 Chromium、Firefox、WebKit 运行；验证键盘操作、焦点、表单标签、对比度和响应式布局。
- 安全 UI 用例：服务端返回的模板名、标签、搜索高亮、文件名包含 HTML/脚本时必须文本化/可信消毒；禁止直接渲染未净化 `v-html`。
- 前后端契约：TypeScript API 类型从固定 OpenAPI 版本生成或校验，CI 中检测接口漂移。

### 5.3 端到端与数据质量

- 追溯图对账：随机生成批次/工艺/零件/检测关系，正向查询结果反向遍历应回到同一来源。
- 属性测试：单位换算、日期边界、浮点精度、空值、极值、Unicode、重复键和嵌套数组。
- 导入对账：输入行数 = 成功 + 失败；成功记录与 Mongo 数据、PostgreSQL 计数、审计事件一致；重复提交不重复入库。
- 文件对账：PostgreSQL 元数据、GridFS 文件/分块、SHA-256 和业务关联一一对应；定时对账能报告且安全清理孤儿。
- 时间一致性：NTP 偏差、跨午夜/月末、夏令时输入、设备迟到/乱序和重复时间戳。

## 6. 安全测试计划

1. 认证：用户名枚举、验证码绕过/复用、暴力破解、账号锁定竞态、固定会话、Token 篡改、过期、刷新重放、退出和改密失效。
2. 授权：页面隐藏与 API 权限一致；方法、数据域、GridFS、搜索、导出、后台任务逐一验证。
3. 输入：SQL/NoSQL/表达式/CSV 公式/路径注入，JSON 深度与大小，分页和排序字段注入，恶意文件名及压缩包。
4. Web：XSS、CSRF（若使用 Cookie）、CORS、CSP、点击劫持、安全响应头、开放重定向、错误信息泄露。
5. API：批量赋值、过度数据暴露、无限分页、导出/登录/上传限流、幂等键猜测、Webhook 签名重放。
6. 供应链与配置：密钥不入库，生产禁用默认密码和调试端点；依赖/容器镜像无高危漏洞；Actuator 和数据库端口不公网暴露。
7. 审计：安全事件自身可审计；审计内容脱敏；普通业务管理员、数据库应用账号均无更新/删除审计记录的权限。

安全上线门禁：高危/严重漏洞为 0；中危若未修复必须有书面风险接受、补偿控制和截止时间。权限绕过、审计缺失、凭据泄露不允许风险接受后带病上线。

## 7. 性能、容量与稳定性

### 7.1 固定基线

- 普通查询 p95 ≤ 2 秒；复杂组合/全链路追溯 p95 ≤ 5 秒；报表/同步导出入口 p95 ≤ 10 秒。
- 100 并发在线用户，场景比例建议：查询 55%、动态录入 15%、文件操作 10%、审核发布 10%、管理与其他 10%。
- 日采集 100 万条；测试库至少准备 30 天等效数据和代表性大文件，避免只在空库测性能。
- 系统可用率目标 ≥ 99.5%；需明确统计窗口、计划停机是否排除，以及 RTO/RPO。

### 7.2 场景

- 逐级升压、100 并发稳态 60 分钟、峰值/突发、4～8 小时耐久、存储接近容量阈值。
- 同一数据集并发创建/导入/审核/导出；大 Excel 流式导出客户端中断；GridFS 分片上传暂停、恢复、重复最后一片。
- 设备突发上报、MES 回调重复、外部接口 50% 超时、消息/任务积压和恢复。
- PostgreSQL 慢查询/连接池耗尽、MongoDB 节点切换、Redis 重启、磁盘空间不足、Nginx 超时。
- 采集 CPU、内存、GC、线程、连接池、Redis 命中率、数据库锁/慢查询、队列积压、磁盘和网络指标；仅响应码成功但数据丢失视为失败。

建议用 k6 或 Gatling 驱动 HTTP 场景，并用独立对账脚本验证最终数据量、去重键和审计事件。

## 8. 备份、恢复与灾难演练

验收不接受“定时任务执行成功”作为恢复证明，至少执行：

1. PostgreSQL 全量备份 + WAL/PITR；MongoDB/GridFS 一致快照；Redis 仅对确需持久化的数据验证恢复语义。
2. 恢复到全新、隔离环境，应用使用恢复后的数据启动。
3. 以业务事务 ID/Outbox 水位对齐 PostgreSQL 和 MongoDB，检查附件 SHA-256、数据集计数、审计链和签名记录。
4. 恢复指定历史日期点，并证明恢复点后的操作被正确排除。
5. 模拟单库损坏、误删、密钥丢失、异地备份不可用；记录实际 RPO/RTO。
6. 备份文件加密、访问控制、保留和销毁流程也纳入审计。

当前 `BAK-002` 已按上述第 2、3 项形成软件级证据：`tools/test_cross_store_backup_restore.sh` 只创建临时 PostgreSQL 17/MongoDB 8 容器，制造含 PostgreSQL 附件引用、Mongo 记录及 GridFS file/chunk 的静止恢复点；断言未收敛 Outbox 时拒绝创建、修改任一归档后 HMAC/SHA 校验失败、错误 backupId 不触发破坏性操作，并在同时破坏两库后恢复 Flyway 版本、关键计数、业务值、附件引用和 GridFS 分块。第 1、4、5、6 项中的 WAL/PITR、历史日期点、异地介质、加密保留销毁和实测 RPO/RTO 继续归 `BAK-001` 生产验收，不能由本机演练替代。

### 11.1 当前代码基线的 P0/P1 自动化清单

以下用例是 2026-08-09 代码基线的最小门禁。P0 必须在真实 PostgreSQL、MongoDB、Redis Testcontainers 环境全部通过；Mock 测试不能替代。

| 用例 | 级别 | 场景 | 核心断言 |
|---|---|---|---|
| AUTH-001 | P0 | 匿名注册请求夹带 `departmentId`、`dataScopeId`、`roles`、`status` 等字段 | 用户状态仍为待审核；无数据域；只能得到系统规定的初始角色；响应不回显被忽略的授权字段。 |
| AUTH-002 | P0 | 已登录用户被冻结、删除、撤销角色或数据域后复用旧 access token | 下一次请求立即失败；Redis 会话按规则撤销；不能继续使用 Token 内旧权限。 |
| AUTH-003 | P0 | 同一 refresh token 两个线程同时刷新 | 仅一个成功；另一个 401；只存在一条活动会话，旧 access/refresh 不可再用。 |
| AUTH-004 | P1 | 注册/刷新字段为 null、空串、超长 Unicode；未知用户名高频登录 | 返回确定的 400/401 而不是 500；错误信息不枚举用户；Redis 键和请求体有长度/频率边界。 |
| AUTH-005 | P0 | 使用生产 profile 启动空库，完成管理员引导和改密后保留原引导环境变量重启；尝试文档/前端展示的默认凭据 | 生产不创建已启用的公开默认管理员；引导账号在改密前仅可访问改密/退出；引导只成功一次，重启不得把新密码重置回环境变量中的密码。 |
| AUD-001 | P0 | 两个应用实例并发写入至少 100 条审计 | 审计链只有一个线性头；每条 `previous_digest` 精确指向上一条；逐条 HMAC 可从数据库字段重算。 |
| AUD-002 | P0 | 在业务 UPDATE 后、审计 INSERT 前注入异常 | 同一 PostgreSQL 事务整体回滚，不得出现“业务成功但无审计”。 |
| AUD-003 | P0 | JWT 密钥轮换与审计密钥轮换 | JWT 轮换不影响历史审计；按 `audit_key_id` 验证历史链；篡改 details、用户、时间、keyId 或链指针均被发现。 |
| AUD-004 | P0 | 定时 Reconciler 完成跨库事件 | 审计归属原操作人而非 `anonymous`，保留原请求时间/最终处理时间及补偿标识。 |
| AUD-005 | P0 | 非管理员且仅有 A 数据域的质控用户查询审计日志 | 不返回 B 域的 before/after、记录 ID、账户信息或其他业务细节；全局验链权限与数据查阅权分离。 |
| SCOPE-001 | P0 | 部门 A 用户用部门 B 的模板、数据集、Mongo ObjectId、追溯实体 ID 访问列表/详情/修改/导出 | 所有路径一致拒绝；响应不泄露名称、计数、附件和资源存在性。 |
| TPL-001 | P0 | 创建者提交模板后尝试自审；第二名审核员审批 | 创建者 403；授权且可访问该域的不同审核员成功；审计记录审核含义和双方身份。 |
| TPL-002 | P0 | 发布模板后直接修改/删除；已有数据集引用模板后更新模板 | 发布版本不可原地变化；数据集固定 `template_id + template_version`；历史数据仍按原版本解释。 |
| DATA-001 | P0 | 同一 create 请求以相同幂等键并发/串行重放 10 次 | Mongo 仅一条记录；`data_count` 只加 1；Outbox 仅一条 DONE；审计仅一个业务效果。 |
| DATA-002 | P0 | 同一幂等键换数据集、换记录 ID、换操作、换目标数据或原因 | 返回 409；任何 Mongo/PG 业务数据、计数和审计均不变化。 |
| DATA-003 | P0 | 在“Outbox 已提交/索引创建前/Mongo 写后/PG 完成前/审计前”逐点杀进程或断网 | 客户端同键重试或 Reconciler 后得到恰好一次效果；无孤儿、重复、计数漂移；事件最终进入明确终态。 |
| DATA-004 | P0 | UPDATE/DELETE 在 Mongo 成功后令 PostgreSQL 或审计失败 | Reconciler 完成原主体归属的 before/after/reason 审计；删除计数恰好减 1；重放不重复减计数。 |
| DATA-005 | P0 | 两用户以相同 `expectedVersion` 并发更正同一记录 | 仅一人成功；另一人 409；失败事件为不可重试业务终态，不能被 Reconciler 永久扫描。 |
| DATA-006 | P0 | 更正/删除理由为空、before/after 被篡改、删除后再次更正 | 空理由 400；审计保存可信前后值和版本；已删除数据不能通过普通查询/导出读取。 |
| DATA-007 | P1 | 旧集合含多条没有 `outboxEventKey` 的记录时首次创建新记录 | partial unique index 可成功建立；历史记录不冲突；相同事件键仍保持唯一。 |
| DATA-008 | P1 | CSV 值和字段名分别以 `= + - @ tab CR` 开头；100 万行导出并中途断开客户端 | 公式被中和；服务端使用游标流式输出且内存稳定；导出尝试和完成/中断均有审计。 |
| DATA-009 | P1 | 字段定义含重复 key、未知类型；记录含错类型、未知字段、非法日期、越界数值、错误单位 | 创建/录入返回逐字段 400；不落 Mongo、不产生成功 Outbox；与模板 Schema 的约束一致。 |
| DEVICE-001 | P0 | 同一设备事件重复/并发上报 10 次，中途超时后重试；再用同一键更换测点、值或时间 | 相同请求仅产生一条测量；换内容返回 409 且不改变 `last_seen_time`；保存设备时间、服务器接收时间、事件唯一键、请求指纹、设备/服务主体和原始摘要。 |
| DEVICE-002 | P0 | 使用人员 Token、伪造设备请求、过期/重放签名和被撤销设备凭据上报 | 仅正式设备/服务账号可写；签名、时间窗、nonce 和数据域均受服务端验证。 |
| DEVICE-003 | P0 | 有 `device:read` 但无管理权的用户调用设备列表/详情 | 不回显连接密钥、密码、Token、SNMP community 或完整内网连接配置；审计也不记录明文凭据。 |
| DASH-001 | P0 | A 域用户查看看板设备趋势、审计计数和全局搜索 | 所有指标与结果统一按数据域/公开性规则过滤，不通过汇总数暴露 B 域活动。 |
| TRACE-001 | P0 | A 域根节点经无权 B 域节点连接到有权 C 域节点 | 查询不会穿越 B，也不返回断开的 C；边和节点均无跨域侧信道。 |
| TRACE-002 | P0 | 构造入边、出边、环和多层链，分别查询 forward/reverse/both、深度 1/2 | 只返回实际方向与深度内遍历的边；无 N+1 层；环不重复/不超时。 |
| TRACE-003 | P1 | 非管理员跨域建边、同节点自环、非法 direction/关系类型、图超过 1000 边 | 分别返回 403/400/受控超限响应；数据库无非法关系；无高 CPU/长事务。 |
| ROLE-001 | P0 | 用最终五类业务角色执行权限矩阵 | 研发、生产、质控、管理员/运维、决策层各自完成必要任务；质控可录入质量记录；访客只能读取明确公开内容。 |
| ADMIN-001 | P0 | 唯一启用管理员移除自己的 ADMIN 角色/停用自己；两个管理员并发互相停用或移除 ADMIN | 事务锁下始终保留至少一名启用管理员；失败变更整体回滚；审计含角色/数据域/部门前后值和变更原因。 |
| MIG-001 | P0 | 从空库顺序执行全部 Flyway migration，再重复启动；从 V1 快照升级到最新 | 两条路径均成功；种子外键、序列、索引、触发器正确；迁移不可静默修改历史版本。 |
| CFG-001 | P1 | 以生产 profile 缺少 JWT/审计/数据库密钥启动 | 启动应失败，不得回退到 `dev-only` 密钥或默认数据库密码；日志不打印任何密钥。 |
