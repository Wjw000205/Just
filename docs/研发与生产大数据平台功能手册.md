# 研发与生产大数据平台功能手册

> 版本：V1.0（基于当前代码 V33）
> 代码基线：`master` / `537a0a4`
> 编制日期：2026年8月16日
> 适用对象：平台普通用户、研发/生产/质量人员、审核员、数据管理员、系统管理员与运维人员

## 1. 手册说明

### 1.1 文档目的

本手册说明研发与生产大数据平台当前代码中的页面、操作、权限、数据边界和运维功能，帮助用户完成从登录、数据建模、数据录入、审核发布、文件管理、追溯检索，到治理、生命周期、外部集成和系统管理的完整操作。

### 1.2 功能状态标识

| 标识 | 含义 | 使用要求 |
|---|---|---|
| 正式功能 | 已连接后端接口，数据写入 PostgreSQL、MongoDB、GridFS 或 Redis，并受权限和审计控制 | 可按本手册执行；上线前仍需完成部署与业务验收 |
| 混合展示 | 页面同时展示真实平台数据和演示指标/入口 | 以页面中的“真实运行数据”“现有平台能力”区域为准 |
| 前端原型 | 用于展示未来业务信息架构和交互，不写入业务数据库 | 不可作为已投产业务能力或正式报表依据 |
| 外部边界 | 软件已提供通用框架，但依赖厂商、网络、介质或法规签署 | 必须完成专项接入、演练或书面确认后启用 |

### 1.3 系统技术组成

| 组件 | 主要职责 |
|---|---|
| Vue 3 + Element Plus | 管理端页面、动态表单、追溯图、上传与导出交互 |
| Spring Boot 3 | 认证、业务规则、权限、接口、任务调度和一致性补偿 |
| PostgreSQL 17 | 用户、权限、元数据、工作流、电子签名、审计和权威状态 |
| MongoDB 8 | 动态数据集记录与状态投影 |
| GridFS | 文件内容、分片上传和附件存储 |
| Redis 8 | 验证码、登录/二级密码锁定、会话、一次性确认凭据和限流 |

### 1.4 使用前提

- 使用受支持的浏览器访问部署地址；本地开发默认地址为 `http://127.0.0.1:5173`。
- 账号必须处于启用状态，并已分配至少一个角色。
- 页面是否出现由菜单/路由权限决定，数据是否可见还受数据域和选择性共享规则限制。
- 删除、导出、权限变更、共享等敏感操作需要二级密码签发的一次性确认凭据。
- 页面显示“原型”“DEMO”或“新增能力为前端演示”时，该页面不会写入数据库。

## 2. 账号、安全与个人中心

### 2.1 登录

1. 打开登录页。
2. 输入用户名和密码。
3. 计算图形验证码并输入结果；点击验证码图片可刷新。
4. 点击“进入平台”。
5. 首次登录或管理员重置密码后，系统会强制进入改密页。

安全规则：用户名最长50字符，密码最长128字符；登录和验证码接口有请求体上限、单IP与全局限流；密码连续失败会触发账号锁定；刷新令牌放在 HttpOnly、SameSite=Strict Cookie 中并轮换消费。

### 2.2 首次强制改密

首次登录时输入当前引导密码、新密码和确认密码。新密码要求8至20位，并同时包含大写字母、小写字母和数字。修改成功后当前会话被撤销，必须用新密码重新登录。

### 2.3 自助注册

自助注册由部署参数控制，默认关闭。开启后：

1. 在登录页点击“申请平台账号”。
2. 选择邮箱或手机作为验证渠道；未选择渠道的联系方式不会写入账号。
3. 填写用户名、真实姓名、密码和图形验证码。
4. 获取6位验证码。验证码5分钟内有效、只能使用一次，并绑定渠道、目标和注册用途。
5. 提交申请后账号保持停用，仅保留访客占位角色。
6. 管理员在“系统管理 > 用户与组织 > 注册审核”中批准或驳回。
7. 批准时必须一次性分配正式角色、直接数据域和可选部门，账号才可登录。

本地 `SIMULATED` 通知模式只用于自动验收，不代表生产邮件或短信供应商已开通。

### 2.4 个人中心

个人中心显示用户名、姓名、部门、角色、直接数据域、有效读取域、选择性共享和最近登录时间。用户可以：

- 修改姓名、邮箱和手机号；
- 修改登录密码，成功后退出所有会话；
- 首次设置或修改6位二级密码；
- 查看直接授权与通过用户/角色/部门获得的共享范围。

首次设置二级密码必须复核当前登录密码。二级密码修改、审核、发布等路径共享失败计数；连续5次错误锁定30分钟，并记录独立安全审计。

### 2.5 安全退出与会话撤销

点击右上角头像选择“安全退出”。管理员停用账号、变更角色/数据域、重置密码或批准注册时会撤销目标账号的既有会话。权限和数据域变化从下一次请求起生效。

## 3. 导航、权限与数据访问模型

### 3.1 十个导航域

| 编号 | 导航域 | 当前内容 |
|---|---|---|
| 01 | 数据驾驶舱 | 角色驾驶舱、真实平台指标、决策报表 |
| 02 | 数据资产中心 | 资产/材料/工艺/产品/性能原型，设备、文件、数据集正式功能 |
| 03 | 全链路追溯 | 正反向追溯正式功能，追溯历史原型 |
| 04 | 研发数据中心 | 项目、实验、工艺实验、仿真原型 |
| 05 | 生产数据中心 | 生产总览/工单/工序/批次/实时原型，设备运行正式功能 |
| 06 | 质量数据中心 | 检验、CT/金相、硬度/厚度、疲劳、缺陷原型 |
| 07 | 数据分析 | 工艺、性能、批次、相关性、趋势分析原型 |
| 08 | 数据集成中心 | 集成配置/映射/作业/死信正式功能与配套展示入口 |
| 09 | 数据治理 | 分类、标签、字典、模板、生命周期正式功能；主数据等原型 |
| 10 | 系统管理 | 用户、角色、数据域、菜单、共享、审计、平台配置正式功能；系统日志原型 |

### 3.2 权限的三层判断

1. **模块权限**：决定能否进入页面或调用接口，如 `dataset:read`。
2. **操作权限**：决定能否创建、更新、审核、导出、下载或删除，如 `dataset:export`。
3. **资源范围**：决定能操作哪些数据域、数据集或业务记录，来源包括直接数据域、部门/角色共享和用户共享。

共享只扩大读取范围，不会授予接收者原本没有的模块权限，也不会授予写权限。

### 3.3 默认角色

| 角色 | 典型职责 |
|---|---|
| 系统管理员 ADMIN | 全平台治理、用户权限、共享、集成、审计与运维 |
| 研发人员 RND | 模板/数据集录入、导入导出、追溯与研发数据维护 |
| 生产操作人员 PRODUCTION | 生产数据录入、设备管理与采集 |
| 质量控制人员 QUALITY | 质量数据、独立审核、发布与审计查看 |
| 企业决策层 EXECUTIVE | 驾驶舱、已发布数据、报表与追溯查看 |
| 审核员 AUDITOR | 模板/记录独立审核、发布、审计和证据查看 |
| 数据管理员 DATA_ADMIN | 模板、数据集、治理和生命周期管理 |
| 访客 GUEST | 受权限与数据域限制的只读访问 |

实际权限以系统管理中的角色配置为准；一个用户可绑定多个角色，权限取并集。

### 3.4 数据域

数据域可表示全局、部门、项目或产品线。数据集、模板、设备、追溯实体和附件等资源均绑定数据域。非管理员只可访问有效数据域；数据域停用后相关访问即时收口。直接数据域通常代表可写范围，共享范围通常只提供读、导出或下载。

### 3.5 选择性共享

管理员可把数据域或单个数据集共享给用户、角色或部门：

- `READ`：查看、检索、看板和基础附件元数据；必选；
- `EXPORT`：允许数据导出；需接收者同时具有导出模块权限；
- `DOWNLOAD`：允许附件内容下载；需接收者同时具有文件读取权限。

共享可设结束时间，过期自动失效；撤销需填写原因并进行二级确认。共享规则不会改变资源所有权、创建者或直接数据域。

### 3.6 二级确认

用户在个人中心设置6位二级密码。敏感操作弹窗签发5分钟、一次性的 proof，并绑定当前用户、会话、用途、HTTP方法、目标、请求载荷和权限安全戳。proof 不能跨用户、跨会话、跨目标、换载荷或重放。

适用场景包括：

- 数据集、记录、文件、模板和用户删除；
- 数据、附件包、驾驶舱和审计导出；
- 用户启停、授权、重置密码和批量导入；
- 注册审核、角色/数据域/部门变更；
- 共享创建与撤销；
- 集成死信人工重放。

## 4. 数据驾驶舱与全局检索

### 4.1 数据驾驶舱

驾驶舱提供管理层、研发、生产和质量四个视角，可切换趋势、状态、异常、数据来源拓扑和平台指标组件。

特别说明：角色卡片、近8周趋势、异常列表和部分来源拓扑属于演示视图；“现有平台真实运行数据”区域连接真实 `/api/dashboard` 与 `/api/dashboard/report`，展示完整模板数、数据集数、已发布记录数、可见记录数、发布率和设备在线率。

拥有 `dataset:export` 权限的用户可点击“导出决策报表”，输入二级密码后下载当前授权范围的 CSV。组件显隐配置只保存在当前前端会话，不会写入全局配置。

### 4.2 顶部快捷搜索

顶部搜索框输入至少2个字符，可查询当前用户有权查看的模板、数据集和追溯实体。点击结果会跳转到模板、数据集详情或追溯根节点。快捷搜索不替代高级检索。

### 4.3 高级检索

高级检索支持：

- 资源类型：模板、数据集、数据记录、设备、追溯实体；
- 条件字段：关键词、材料、工艺、批次、设备、产品型号、分类、类型、状态；
- 操作符：模糊、精确等；多个条件按 AND 组合；
- 时间范围、分页、排序字段与升降序；
- 中文全文检索、高亮、个人历史和热门建议。

结果会同时执行模块权限、数据域、共享有效期和记录发布状态判断。搜索历史和建议按用户隔离；可一键清空个人历史。高亮由服务端安全生成，不执行用户输入的 HTML。

## 5. 模板中心

### 5.1 模板类型与结构

模板由基本信息、章节、字段和约束组成。字段 key 应以英文字母开头，可配置文本、数字、日期、布尔、枚举等类型，以及必填、长度、数值上下限、日期范围、正则表达式、单位和选项。

模板分为完整模板和片段。只有已发布、启用的完整模板可用于创建数据集；模板片段可用于标准设计，但不能直接绑定数据集。

### 5.2 新建与编辑草稿

1. 进入“数据治理 > 模板中心”。
2. 点击“新建模板”。
3. 填写名称、类型、标签、说明、数据域和来源。
4. 添加章节，再添加字段并配置约束。
5. 保存草稿。

字段 key 在同一模板内必须唯一。待审核或已发布模板被冻结，不能原地修改。

### 5.3 提交、审核与发布

模板流程为：草稿 → 待审核 → 审核通过并发布，或驳回。创建者不能审核自己的模板。审核员填写审核意见，批准后模板成为不可变发布版本；驳回后由有权限人员复制为新草稿继续修改。

### 5.4 版本历史与恢复

模板详情显示完整版本历史。可查看指定版本、比较内容，并将历史版本“恢复为新草稿”。恢复不会改写历史版本，也不会把已发布版本变回可编辑状态。

### 5.5 启停、收藏和删除

- 审核人员可填写原因启用或停用模板；停用后不能被新数据集使用。
- 用户可收藏或取消收藏模板。
- 只有满足删除条件的模板可删除，删除需要二级确认；已被数据集或历史对象引用时会被拒绝。

## 6. 数据集与动态记录

### 6.1 创建数据集

1. 进入“数据资产中心 > 通用数据集”。
2. 点击“创建数据集”。
3. 选择已发布、启用的完整模板，或选择自定义结构。
4. 填写名称、编码、分类、标签、说明、数据域和重要性。
5. 保存。

模板模式会复制指定模板版本的章节、字段和全部校验约束，不会随模板后续版本自动漂移。自定义结构应明确标识并自行维护字段。

### 6.2 数据集编辑、收藏、共享和删除

- 可按关键字、分类查询，进入详情或收藏。
- 空数据集可编辑结构和数据域；已有记录时字段结构冻结；存在记录、历史归档或附件时，数据域、模板和删除操作会受到保护。
- 点击“共享”跳转或打开共享规则，由有权限人员选择数据域/数据集、接收者和操作范围。
- 删除数据集需要二级确认，且必须没有阻断性记录、附件或可恢复归档历史。

### 6.3 在线新增记录

进入数据集后，页面按字段定义动态生成表单。填写完成后保存为草稿。每次创建使用唯一 `X-Idempotency-Key`，网络重试不会重复生成记录。

### 6.4 受控更正

草稿或驳回记录可以更正。更正必须填写原因并提交当前版本号，系统通过版本和跨库存储预占防止旧页面覆盖新数据。更正会生成新版本并保留审计前后值。

### 6.5 记录删除

仅允许处于可删除状态、没有受保护附件且没有生效保留例外的记录删除。删除时填写原因、携带当前版本和幂等键，并完成二级确认。已审核、已发布或生命周期转换中的记录不能直接删除。

### 6.6 批量导入

支持 CSV、JSON、XLSX：

1. 下载或参照数据集字段结构准备文件。
2. 在记录页点击“批量导入”。
3. 选择格式和文件并执行导入。
4. 在导入作业中查看总数、成功数、失败数和逐行错误。

导入按行校验与落库；合法行可以成功，错误行保留行号、原始值摘要和原因。导入不会跳过字段约束、数据域或工作流规则。

### 6.7 数据导出

支持 CSV、JSON、XLSX，可选择一个或多个字段。导出前需要 `dataset:export`、资源级 `EXPORT` 权限和一次性二级确认。系统会：

- 过滤当前用户无权访问的记录；
- 对电子表格公式前缀做中和处理；
- 对配置的敏感字段做脱敏；
- 记录格式、字段、条数、大小、成功或失败审计；
- 使用不可缓存的一次性下载票据，避免超长URL和浏览器大Blob驻留。

选择“含附件包”时会生成 ZIP，包含数据文件、附件清单和有 `DOWNLOAD` 权限的附件。系统先在受控临时目录校验附件大小和 SHA-256，再开始响应；受附件数量、总大小和并发上限控制。

## 7. 记录审核、发布与电子签名

### 7.1 状态流程

| 状态 | 含义 | 允许操作 |
|---|---|---|
| DRAFT | 草稿 | 编辑、删除、提交审核 |
| PENDING_REVIEW | 待审核 | 独立审核，不允许普通编辑 |
| APPROVED | 审核通过 | 由发布人员签名发布 |
| REJECTED | 驳回 | 受控更正后回到新版本草稿 |
| PUBLISHED | 已发布 | 普通读者可见，禁止原地修改 |
| CORRECTING / DELETING | 跨库存储转换态 | 系统占用，禁止并发工作流或附件写入 |
| ARCHIVING / ARCHIVED / RESTORING | 生命周期状态 | 按归档恢复规则操作 |

### 7.2 提交审核

记录所有者在草稿状态点击“提交审核”，填写提交原因。提交后记录被冻结，等待独立审核。

### 7.3 独立审核

审核人必须具有 `dataset:audit`，且不能审核自己创建的记录。选择批准或驳回，填写原因并输入6位二级密码。系统保存审核含义、版本、签署人、时间、来源IP、记录摘要和附件清单摘要。

### 7.4 签名发布

已批准记录由具有 `dataset:publish` 的人员输入原因和二级密码发布。发布后普通读者可见。发布签名与审核签名均不可更新或删除。

### 7.5 签名证据与验真

“签名证据”显示签署人、含义、原因、时间、来源IP、密钥版本、记录摘要、附件摘要和证据摘要。点击验真可按当前或历史审计密钥重算并校验列值、载荷和 HMAC。验真失败时应停止发布/交付并联系安全人员。

## 8. 文件资料库与记录附件

### 8.1 业务绑定

文件必须绑定业务类型、业务引用和数据域。常见绑定包括数据集、数据集记录、追溯实体等。文件列表和下载会重新复核当前业务对象权限，不能仅凭文件ID绕过数据域。

### 8.2 批量上传

普通批量上传单批最多20个文件。系统逐个计算 SHA-256、写入 GridFS 并保存 PostgreSQL 元数据；部分失败时返回每个文件的成功/失败结果。

### 8.3 大文件分片与断点续传

文件资料库支持会话式上传：

1. 浏览器按文件指纹创建或恢复上传会话。
2. 按默认4MB分片上传，每片携带 `Content-Range` 和 SHA-256。
3. 可暂停，重新选择同一文件后继续缺失分片。
4. 完成时校验分片连续性、整体大小和整体 SHA-256，再登记正式附件。
5. 可取消并清理会话。

默认单文件上限20GB；每用户活动会话数、待完成总字节和会话有效期均可配置。过期或不可恢复失败后应取消旧会话并重新选择文件。

### 8.4 预览与下载

可安全内联预览 PDF、纯文本、PNG、JPEG、GIF、WebP 和 BMP。HTML、SVG、3D工程文件等按附件下载处理。下载支持 HTTP Range、后缀范围和206响应，非法范围返回416。响应设置 `no-store`、`nosniff` 和沙箱安全头。

### 8.5 删除与一致性巡检

附件删除需要 `file:delete`、业务对象权限和二级确认。记录处于待审核、已批准、已发布、删除或生命周期转换状态时，附件增删会按证据冻结规则受限。后台巡检不会把 Mongo/GridFS 临时故障误判为文件丢失，并保护分片上传和恢复中的临时内容。

### 8.6 病毒扫描边界

代码提供“病毒扫描必须启用”安全开关；当前未集成生产扫描器。若生产要求扫描，应接入扫描器并启用强制开关，否则不可宣称恶意文件处置闭环。

## 9. 全链路追溯

### 9.1 实体与关系

正式追溯实体支持材料批次、工艺批次、产品、质量检测、性能测试和缺陷。具有 `trace:write` 的人员可创建实体和有方向的关系；每个实体绑定数据域、来源系统、来源记录号、版本和结构化业务属性。

### 9.2 正向、反向和双向追溯

1. 在“全链路追溯 > 追溯搜索”选择起点。
2. 选择正向、反向或双向。
3. 设置深度1至10。
4. 点击“开始追溯”。

SVG 图保留业务原始箭头方向，支持材料 → 工艺 → 产品 → 检测/缺陷，也支持从缺陷反查产品、工艺和材料。系统限制深度和节点规模，防止循环无限展开。

### 9.3 节点证据

单击节点后可查看：

- 来源系统、来源记录号、记录版本、记录时间；
- 结构化业务参数；
- 关联附件名称、大小、上传人、时间和 SHA-256；
- 最新不可变审计事件、操作者、动作、详情摘要和记录摘要。

节点、关系、附件和审计详情均逐项执行数据域过滤。没有 `file:read` 时附件区域会显示无权限；只有READ共享而没有DOWNLOAD时可见元数据但不能取得附件内容。

### 9.4 追溯历史原型

“追溯记录”当前是前端原型，用于展示最近查询、收藏链路和导出快照的未来信息架构；不写入正式追溯历史表，不应作为审计证据。

## 10. 设备与采集

### 10.1 设备登记

具有 `device:manage` 的人员可登记设备编码、名称、类型、型号、协议、连接配置和数据域。连接配置使用 AES-GCM 加密存储，不在页面回显明文。登记成功仅返回一次设备采集密钥，应立即保存在设备密钥管理系统。

### 10.2 设备密钥轮换

点击“轮换设备密钥”后旧密钥立即失效，新密钥也只返回一次。更换设备端配置前应安排停机窗口，避免采集中断。

### 10.3 人员会话采集

管理人员可通过设备接口写入测量，携带唯一幂等键。测量包含指标名、数值或文本值、单位、质量标记、测量时间和原始数据。原始测量不可变，并记录来源归属。

### 10.4 设备专用 HMAC 采集

无人员会话的设备调用 `/api/device-ingest/{deviceCode}/measurements`，携带时间戳、幂等键和 HMAC-SHA256 签名。平台校验设备身份、时间窗口、频率和报文大小，并对身份失败和限流做安全审计。

### 10.5 自动采集与心跳

当前页面支持启用“模拟自动采集”，配置轮询间隔和心跳超时。后台任务更新设备在线/离线状态并写入模拟测量。真实3D打印、Modbus TCP、OPC UA及检测设备适配仍属于外部厂商联调边界。

## 11. 数据生命周期

### 11.1 数据重要性与保留策略

数据集重要性支持 LOW、NORMAL、HIGH、CRITICAL。策略可按数据域覆盖全局策略，配置在线天数、归档目标、是否自动归档和是否启用。默认策略的自动归档关闭，管理员明确启用后才会由调度任务处理。

### 11.2 到期预览

“到期预览”列出符合策略的已发布记录。手工归档可使用有效策略，不要求该策略开启自动归档；自动任务只选择 `autoArchive=true` 的最终命中策略。

### 11.3 保留例外

对质量调查、诉讼、偏差处置等记录可创建保留例外，填写原因和可选到期时间。生效的保留例外会阻止自动/手工归档，以及记录或证据附件删除。解除保留例外需要版本号和原因。

### 11.4 归档

归档仅适用于已发布数据记录：

1. 锁定工作流并复核策略、数据域和保留例外。
2. 读取 Mongo 记录和关联 GridFS 附件，计算逐项摘要。
3. 生成包含清单、记录和附件的 ZIP，并校验总摘要。
4. 在 PostgreSQL 原子切换归档状态、附件状态和计数。
5. 删除在线副本，保留搜索投影与权威归档清单。

归档目录应挂载到独立备份服务器或NAS；容器本地目录不应作为唯一副本。

### 11.5 归档检索、恢复与重试

归档清单支持状态、关键词和分页检索。恢复前复制不可变临时快照，校验ZIP总摘要、清单、记录摘要和每个附件的大小/SHA-256；校验通过后恢复 Mongo/GridFS 和 PostgreSQL 状态。失败项可按失败阶段重试；陈旧转换由代际租约和对账任务回收，管理员可手工执行 reconcile。

### 11.6 当前范围

生命周期正式覆盖已发布的数据集记录。设备时序、追溯实体和其他业务资源尚未纳入统一策略；独立NAS和正式恢复演练也需部署侧完成。

## 12. 外部系统集成

### 12.1 集成配置

集成管理支持 MES、PLM、ERP、IoT 等系统。配置包含：

- 稳定系统编码和名称；产生作业后系统编码不可修改；
- 系统类型、启用状态和精确来源IP白名单；
- 信任域、实体类型、业务键字段、游标字段、来源优先级和来源版本字段；
- 冲突策略、交付模式和目标地址；
- HMAC或OAuth2认证参数；
- 乐观版本号，防止旧页面覆盖新配置。

### 12.2 字段映射与清洗

字段映射支持源字段、目标字段、是否必填、默认值和转换。当前转换包括 TRIM、NUMBER、DATE、UPPERCASE 和单位转换。映射保存使用 `expectedMappingVersion` CAS；接收作业保存映射与处理配置快照，后续修改不会改变已接收事件的解释依据。

### 12.3 HMAC接入

每个系统使用不少于32个UTF-8字节的独立随机密钥。入站 `RDP-HMAC-V1` canonical 绑定协议版本、POST方法、Webhook路径/系统编码、Unix时间戳、幂等键和原始请求体。签名不能跨系统或跨路径复用。

密钥可在页面生成。V33 升级会先失败关闭旧HMAC配置并解密验强；弱密钥或损坏密文保持停用，待交付作业进入人工复核，管理员录入强密钥后 rebase。

### 12.4 OAuth2接入

OAuth2使用RFC 7662自省，必须配置：

- 本平台访问自省端的 client ID/secret；
- 外部调用方独立 AppID，即令牌中的来源 `client_id`；
- issuer、audience、scope、自省URL和自省端主机白名单；
- 来源IP白名单和100至5000ms壁钟超时。

平台校验 active、exp、nbf、issuer、audience、client_id和scope。同一issuer下的来源client_id只能绑定一个集成系统。生产还必须使用受信DNS和出口防火墙，应用白名单不能单独消除DNS rebinding风险。

### 12.5 异步接收、幂等与信任裁决

认证成功后Webhook立即持久化并返回202和jobId，后台处理：

1. 根据幂等键判断重复；同键同载荷复用作业，同键不同载荷返回冲突。
2. 应用接收时的配置和映射快照。
3. 在信任域/实体类型/业务键命名空间内执行来源优先级和版本裁决。
4. 迟到但唯一的事件仍落地，游标只向前推进；更早未决游标会阻止越过。
5. 本地事务提交后，只有被接受事件才进入远端交付。

### 12.6 HTTP交付与凭据快照

HTTP交付使用部署级目标主机白名单。出站 `RDP-HMAC-V1` 绑定方法、目标raw path/query、来源系统、时间戳、幂等键和规范化JSON。远端必须校验签名并按幂等键保证单一业务效果。

待交付作业保存加密凭据快照，因此管理员可以轮换当前密钥；旧作业仍用原版本重试，进入完成、跳过或明确终止后清除快照。后续同一信任键的新版本会等待前序交付完成。

### 12.7 重试、死信、人工重放和对账

- 408、425、429、5xx、超时和 `Retry-After` 进入持久退避；默认阶段为60、300、1800秒。
- 重试耗尽后进入死信/人工复核。
- 人工重放要求 `integration:retry`、说明和 `PRIVILEGE` 二级确认，可选择使用当前映射/交付配置进行rebase。
- 对账会重新读取实际已处理记录，比较目标JSON摘要，并单列交付待处理/失败状态。
- 陈旧PROCESSING/RETRYING租约由后台任务恢复，多实例领取采用数据库锁和token fencing。

### 12.8 接口审计与防护

Webhook固定/分块请求体上限1MB，限流在MVC读取正文前执行。每次到达应用的调用生成请求ID，审计保存方法、路径、请求/响应摘要、字节数、耗时、状态码、认证类型和jobId，不保存Authorization、密钥或原始业务载荷。Nginx在应用前拒绝的运输层超限/连接限流写结构化安全日志。

### 12.9 外部联调边界

通用可靠性和API安全框架已实现；真实MES/PLM/ERP字段、账号、拉取/回写语义、厂商网络和生产OAuth/DNS策略仍需专项联调，不能仅凭本机模拟结果标记为厂商验收完成。

## 13. 审计中心

### 13.1 审计查询

具有 `audit:read` 的用户可按用户、模块、操作、时间范围等条件查询审计。审计记录包含操作者、模块、操作、目标、说明、详情摘要、时间、前序摘要、记录摘要和密钥版本。

### 13.2 审计导出

具有 `audit:export` 的用户可导出当前筛选结果。导出需要二级确认，响应禁止缓存，并记录导出成功或失败审计。

### 13.3 审计链验证

管理员或授权审计人员可执行全链验证：系统按密钥版本重算每条记录摘要并核对前后链。审计表通过数据库触发器禁止更新和删除。发现断链、摘要不一致或未知密钥版本时，应立即停止相关业务、保存证据并执行安全事件流程。

### 13.4 保存期边界

代码实现了不可变与可检测篡改，但“永久保存”与“至少10年”的业务/法规口径仍需质量和法规人员确认，并配置独立长期归档、恢复读取与密钥保管流程。

## 14. 数据治理

### 14.1 科学分类与产业分类

支持树形科学分类、产业分类、父子调整、排序、启停和科学分类到产业分类多对多映射。树操作使用事务锁避免并发成环；在用分类不能删除。

### 14.2 标签

支持标签名称、颜色、分组和状态。标签名称统一规范为小写并避免大小写重复；停用标签不能新绑定。模板和数据集主表字符串与关联表保持同一规范；在用标签不能重命名或删除。

### 14.3 部门与负责人

支持部门树、编码、上级部门、负责人、排序和状态。负责人必须为有效用户；停用或删除负责人前必须先移交。部门删除会检查子部门、用户和共享依赖。

### 14.4 角色与权限

支持角色新增、编辑、启停和删除；权限以模块树多选。角色修改使用版本CAS。非管理员只能授予自己持有且权限不超出自身的角色；ADMIN角色必须保留全部启用权限，避免治理自锁。角色被用户或共享引用时不能删除。

### 14.5 数据域

支持部门、项目、产品线等数据域类型，维护编码、名称、说明、状态和版本。数据域被模板版本、数据集、设备、归档历史或共享引用时不能删除。非管理员不能授予GLOBAL或自身未直接拥有的数据域。

### 14.6 数据字典

支持字典与字典项新增、编辑、启停、排序和删除。设备协议、数据重要性等业务字典会在使用时校验；被设备、数据集或生命周期策略引用的字典项不能删除。

### 14.7 菜单权限

支持菜单树、名称、编码、路由、图标、权限码、排序和状态。父菜单停用后子菜单不会出现在动态导航。菜单只控制可见性，后端接口仍独立执行权限校验。

### 14.8 平台界面配置

可设置主色、基础字号、圆角和内容间距，保存后全局生效。配置使用版本CAS和二级确认；登录后的主布局读取配置并写入CSS变量。

### 14.9 主数据、元数据、单位和数据质量原型

“主数据”“元数据”“单位管理”“数据质量”目前为前端原型，展示目录、血缘、规则健康和标准对象的未来界面，不写入正式治理表。正式治理能力以分类、标签、部门、角色、数据域、字典、菜单和界面配置为准。

## 15. 系统管理

### 15.1 注册审核

管理员按用户名/姓名和状态筛选申请。列表仅显示脱敏的已验证目标。批准时选择角色、直接数据域、部门并填写审核意见；驳回时填写理由。审核使用版本、二级确认和事务互斥，批准/驳回并发只有一个成功。通用启用接口不能绕过待审状态。

### 15.2 用户管理

支持查询、新增、编辑基本资料、授权、启停、重置密码、逻辑删除和批量导入：

- 新增用户时分配初始角色、数据域、部门和状态；
- 编辑资料不允许夹带部门授权，部门变更只能走授权接口；
- 授权可多选角色和直接数据域，并设置部门和原因；
- 启停、授权和删除使用版本/锁和二级确认；
- 非管理员不能管理ADMIN或权限超出自身的目标；系统保证至少一名启用管理员；
- 重置密码返回一次性临时密码，旧会话和二级密码被撤销；关闭弹窗后不再显示；
- 用户被设为部门负责人时，停用/删除前必须先移交。

### 15.3 用户批量导入

支持 CSV/XLSX，表头为：`username`、`realName`、`email`、`phone`、`departmentCode`、`roleCodes`、`scopeCodes`、`status`；多个角色或数据域用 `|` 分隔。上传前二级确认绑定原因、文件大小和SHA-256，不能换文件复用proof。结果逐行显示成功、失败和一次性临时密码。

### 15.4 共享管理

系统管理页可查询规则状态、资源、接收者、操作、有效期和原因。创建或撤销规则均需要二级确认和审计；撤销从接收者下一次请求起失效。

### 15.5 角色权限与数据域查看

系统管理页提供角色和数据域摘要；完整CRUD在“数据治理/系统管理”的治理页面完成。

### 15.6 系统日志原型

“系统日志”当前为前端原型，用于展示登录、接口、任务和异常日志的未来检索界面。正式证据以审计中心、Actuator/Prometheus和Nginx结构化日志为准。

## 17. 运维、健康与备份恢复

### 17.1 健康与监控

顶部状态每30秒访问 `/actuator/health`，显示“服务正常/服务异常”。Actuator同时暴露 health、info、metrics和prometheus。生产应由监控系统采集指标和告警，不能只依赖浏览器指示灯。

### 17.2 容器化启动

正式Compose由 PostgreSQL、MongoDB、Redis、后端和Nginx/Vue组成。复制 `.env.example` 后替换所有示例密码和密钥，再使用 app profile 启动。生产必须启用TLS、安全Cookie、受信代理来源IP和持久归档卷。

### 17.3 跨库一致备份 BAK-002

停写维护窗口下，工具生成同一逻辑恢复点：

- PostgreSQL custom dump；
- MongoDB/GridFS archive；
- Flyway版本、关键表/集合计数；
- PostgreSQL可用附件引用、GridFS文件/分块清单；
- 每个文件SHA-256和版本化HMAC manifest。

创建和恢复前必须停止所有写入者；存在未收敛Outbox、生命周期转换、分片上传或集成租约时拒绝备份。Redis不进入耐久包，恢复后应清空短期状态并要求用户重新登录。

### 17.4 备份验证与恢复

恢复前先离线验证归档和HMAC，使用精确backupId二次确认；恢复后自动核对Flyway、计数、附件引用和GridFS分块。备份包权限应为0600，并保存于加密介质。HMAC只提供完整性与来源证明，不提供加密保密。

### 17.5 仍需部署侧完成的能力

- PostgreSQL WAL/PITR和实时副本；
- 周全量、日增量和异地介质；
- 独立NAS/归档服务器与生产RPO/RTO演练；
- 真实邮件/短信、病毒扫描、厂商设备和MES/PLM/ERP联调；
- 浏览器E2E、性能、渗透、长期可用性和法规签署。

## 18. 常见问题与错误处理

| 现象/状态 | 常见原因 | 处理建议 |
|---|---|---|
| 400 | 字段格式、版本、状态或业务约束不满足 | 阅读提示，刷新详情后按当前版本重试 |
| 401 | 未登录、会话过期、设备/HMAC/OAuth认证失败 | 重新登录；设备/集成检查时间戳、密钥、canonical和令牌 |
| 403 | 缺模块权限、数据域或资源操作权限 | 联系管理员核对角色、直接数据域和共享操作 |
| 404 | 资源不存在，或系统为防止枚举而隐藏无权资源 | 从有权列表进入，不要手工猜测ID |
| 409 | 乐观版本冲突、重复幂等键变载荷、状态占用或依赖删除 | 刷新页面；不要重复旧表单；检查关联对象 |
| 413 | 登录/注册、Webhook或文件超过上限 | 缩小请求；大文件使用分片上传 |
| 416 | Range请求不合法 | 使用合法单范围或重新完整下载 |
| 428 | 缺失、过期或绑定不一致的二级确认proof | 重新打开二级确认弹窗，对当前操作重新签发 |
| 429 | 登录、验证码、设备或Webhook限流 | 等待窗口恢复，不要持续重试 |
| 503 | Redis失败关闭、外部OAuth/交付超时、归档/存储暂不可用 | 查看审计和健康状态，恢复依赖后按状态机重试 |

操作原则：

- 出现版本冲突时先刷新，不要反复提交旧页面。
- 导出、附件包或大文件操作失败时不要忽略审计提示。
- 审计链、电子签名或归档摘要校验失败时禁止继续发布/恢复。
- 人工修改 PostgreSQL、MongoDB或GridFS可能破坏跨库一致性，只能按批准的运维流程执行。
